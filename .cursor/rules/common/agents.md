# AGENTS.md
Cursor Agent 全局约束规范
仅用于 Python 后端项目

## 基础技术栈约定
1. 主语言：Python 3.11+
2. Web框架：FastAPI
3. 数据验证：Pydantic v2
4. ORM：SQLAlchemy 2.0
5. 数据库：MySQL / PostgreSQL
6. 测试框架：pytest
7. 代码规范：ruff + black

## 开发流程强制规范
1. 新增功能流程：需求梳理 → 数据模型设计 → Schema定义 → 接口定义 → 单元测试 → 业务实现
2. 重构：小步迭代，不要一次性大规模修改代码；保证测试可持续运行
3. Bug修复：优先定位根因，拒绝临时规避方案；提供复现条件与验证方法
4. 数据库变更：先设计模型，再生成迁移脚本（alembic）；禁止直接裸写DDL上线

## 代码分层与结构规范
1. 分层结构：api(路由) → service(业务逻辑) → repository(数据访问)
2. 路由层(api)：只做参数校验、请求转发、响应封装，不编写复杂业务
3. Service层：承载业务规则、事务控制
4. Repository层：封装数据库查询，隔离ORM细节
5. 严格区分三类模型：
   - DB Model：数据库映射模型
   - Schema(Pydantic)：入参/出参模型
   - Domain：领域模型（复杂项目按需使用）
6. 禁止将数据库模型直接作为接口返回对象

## 编码标准
1. 类型提示完整：所有函数参数、返回值标注 typing
2. 使用Pydantic完成入参校验，不在业务代码手写大量if判断
3. 使用自定义业务异常 + 全局异常处理器统一捕获错误
4. 日志规范：关键流程埋日志，携带业务id；禁止打印手机号、密码等敏感信息
5. 配置信息统一读取环境变量/配置文件，禁止硬编码
6. SQL 禁止 SELECT *；注意索引、分页、长查询性能问题
7. 异步代码合理使用 async/await，避免同步阻塞事件循环

## 测试规范
1. 核心业务逻辑必须编写 pytest 用例
2. 覆盖正常流程、边界值、异常场景
3. 使用 fixture 管理测试资源，mock 外部依赖（DB、第三方接口）
4. 单元测试不依赖外部真实服务

## AI输出要求
1. 实现功能前简要输出设计思路；复杂改动列出变更文件清单
2. 提供SQL、迁移脚本时做好注释，区分开发脚本与上线脚本
3. 需要执行命令时标明用途：pip、alembic、pytest等
4. 不要主动推荐 Java、Go 等无关技术方案
5. 需求模糊时主动提问确认，不要自行扩展需求范围

## 禁止行为
- 一次性修改十几个文件的大规模无规划重构
- 忽略空值、并发、事务、资源释放等边界场景
- 在循环内执行数据库查询（N+1问题）
- 写出存在注入风险的拼接SQL
- 在接口中直接暴露内部报错堆栈给前端
