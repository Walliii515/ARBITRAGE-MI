# 阿里云 ECS 从零部署指南

目标：在一台全新的阿里云 ECS 上部署套利系统，并通过浏览器访问前端页面。

本文按 Ubuntu 22.04 LTS 编写。命令默认使用 `root` 用户执行；如果你使用普通用户，请在系统命令前加 `sudo`。

---

## 0. 推荐服务器配置

| 用途 | 配置 | 说明 |
|---|---:|---|
| 试跑/调试 | 2 vCPU / 4 GiB | 可以启动全套服务，建议加 swap |
| 长期实盘 | 4 vCPU / 8 GiB | 推荐，更适合 MySQL + 多个 WS 长连接 |
| 硬盘 | ESSD 40 GiB 起步，推荐 80 GiB | 日志、MySQL、快照表会持续增长 |
| 带宽 | 5 Mbps 起步，推荐 10 Mbps | 行情 WebSocket + 前端访问更稳 |
| 地域 | 香港/日本/新加坡 | 香港可用；若交易所 WS 不稳再换日本/新加坡 |

不需要 GPU，也不要选 ARM。请选择 X86 架构。

## 2. 配置安全组

在阿里云控制台进入 ECS 的安全组，添加入方向规则：

| 端口 | 协议 | 授权对象 | 用途 |
|---:|---|---|---|
| 22 | TCP | 你的本地出口 IP/32 | SSH 登录 |
| 80 | TCP | 你的本地出口 IP/32，或临时 0.0.0.0/0 | HTTP 访问前端 |
| 443 | TCP | 你的本地出口 IP/32，或临时 0.0.0.0/0 | 后续 HTTPS |

不要把 `3306`、`19876`、`19877`、`8081`、`8082` 开到公网。它们只给服务器本机和 Nginx 使用。

查看你的本地出口 IP：

```bash
curl https://ifconfig.me
```

## 5. 2C4G 机器建议添加 swap

如果你买的是 4C8G，可以跳过本节。2C4G 建议加 2G swap，避免前端构建或 MySQL 瞬时内存紧张。

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
free -h
```

## 7. 导入数据库

重要：当前项目没有完整的新库初始化脚本，`src/migrations/*.sql` 只是增量迁移，不包含所有基础表。因此新 ECS 部署最稳的方式是从旧环境导出完整数据库，再导入新服务器。

### 方式 A：从本地或旧服务器导出再导入，推荐

在旧环境导出：

```bash
mysqldump -u root -p \
  --single-transaction \
  --set-gtid-purged=OFF \
  crypto_arbitrage > arbitrage_dump.sql
```

把 dump 上传到新 ECS：

```bash
scp arbitrage_dump.sql root@8.216.57.73:/root/arbitrage_dump.sql
```

在新 ECS 导入：

```bash
mysql -u arb_app -p crypto_arbitrage < /root/arbitrage_dump.sql
```

导入后检查关键表是否存在：

```bash
mysql -u arb_app -p crypto_arbitrage -e "SHOW TABLES;"
```

至少应该能看到这些表中的大部分：

```text
mi_users
mi_binance_spot_info
mi_gate_future_contracts
mi_gate_future_his_funding_rates
mi_gate_future_funding_rate_threshold
mi_trade_position
mi_trade_order
mi_vwap_basis_snapshot
mi_vwap_basis_threshold
```

### 方式 B：空库

不推荐直接空库启动。空库会缺少登录用户、交易表、基础行情表，服务大概率启动后持续报 SQL 错误。

如果确实要从空库开始，需要先补齐完整建表 SQL，再运行 `src/migrations/*.sql`。目前仓库里还没有这份完整初始化 SQL。

## 10. 配置后端环境变量

创建 `/opt/ARBITRAGE-MI/.env`：

```bash
cd /opt/ARBITRAGE-MI
vim .env
```

写入下面内容，并替换密码和 API Key：

```env
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_DATABASE=crypto_arbitrage
MYSQL_USER=arb_app
MYSQL_PASSWORD=123456Aa.

LOG_LEVEL=INFO
LOG_BACKUP_COUNT=30

# Forward strategy：正向 Binance forward 子账户 + Gate forward 子账户
# 四项均为实盘必填；缺失时服务启动失败，不会回退到旧版通用账户变量
FORWARD_BINANCE_API_KEY=<你的 Binance forward API Key>
FORWARD_BINANCE_API_SECRET=<你的 Binance forward API Secret>
FORWARD_GATE_FUTURES_API_KEY=<你的 Gate forward Futures API Key>
FORWARD_GATE_FUTURES_API_SECRET=<你的 Gate forward Futures API Secret>

# Reverse strategy：反向 Binance reverse 子账户 + Gate reverse 子账户
REVERSE_BINANCE_API_KEY=<你的 Binance reverse API Key>
REVERSE_BINANCE_API_SECRET=<你的 Binance reverse API Secret>
REVERSE_GATE_FUTURES_API_KEY=<你的 Gate reverse Futures API Key>
REVERSE_GATE_FUTURES_API_SECRET=<你的 Gate reverse Futures API Secret>

# Binance 主账户资金划转到 Gate 主账户
# 提现目的地只允许由服务端 .env 固定配置，前端和 API 请求不能覆盖
BINANCE_MASTER_FUND_API_KEY=<你的 Binance 主账户资金 API Key>
BINANCE_MASTER_FUND_API_SECRET=<你的 Binance 主账户资金 API Secret>
BINANCE_FORWARD_SUBACCOUNT_EMAIL=<你的 Binance forward 子账户邮箱>
GATE_MASTER_FUND_API_KEY=<你的 Gate 主账户资金 API Key>
GATE_MASTER_FUND_API_SECRET=<你的 Gate 主账户资金 API Secret>
GATE_FORWARD_SUBACCOUNT_UID=<你的 Gate forward 子账户 UID>

# 唯一允许的提币币种、网络和 Gate 主账户充值地址
FUND_TRANSFER_COIN=USDT
FUND_TRANSFER_NETWORK=<Binance API 网络代码，例如 BSC>
FUND_TRANSFER_GATE_DEPOSIT_ADDRESS=<Gate 主账户对应网络的 USDT 充值地址>

EXECUTOR_TIMEOUT_SEC=10
```

资金监控中的“资金划转”固定执行：

1. Binance forward 子账户 Spot → Binance 主账户 Spot。
2. Binance 主账户按固定币种、网络和白名单地址提现。
3. 等待同一 `txId` 在 Gate 主账户确认入账。
4. Gate 主账户 Spot → Gate forward 子账户 Futures。

输入金额是 Binance forward 子账户的总减少额，包含链上手续费。例如输入
`100 USDT`、实时手续费为 `0.01 USDT`，预计 Gate 入账 `99.99 USDT`。
创建任务前和提交提现前都会重新读取实时手续费。

同一时间只允许一个未完成任务。任务存在期间只锁定正向开仓，平仓、保证金
风控和对账兜底继续运行。每个资金动作使用持久化幂等号，接口超时后只查询
交易所状态，不盲目重复提交。明确的提现失败会把资金退回 Binance forward
子账户；无法自动确认的位置会保持锁定并写入铃铛，需在资金划转弹窗重新核验。
任务历史永久保留。

保护 `.env` 权限：

```bash
chmod 600 /opt/ARBITRAGE-MI/.env
```

验证数据库连接：

```bash
cd /opt/ARBITRAGE-MI/src
../.venv/bin/python - <<'PY'
from common.database import db_manager
with db_manager.get_cursor() as cursor:
    cursor.execute("SELECT DATABASE() AS db")
    print(cursor.fetchone())
PY
```

## 13. 配置 Nginx

创建 Nginx 配置：

```bash
vim /etc/nginx/sites-available/arbitrage
```

写入：

```nginx
server {
    listen 80;
    server_name _;

    root /opt/ARBITRAGE-MI/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:19876;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;
    }

    location /ws {
        proxy_pass http://127.0.0.1:19876;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }
}
```

启用配置：

```bash
ln -sf /etc/nginx/sites-available/arbitrage /etc/nginx/sites-enabled/arbitrage
rm -f /etc/nginx/sites-enabled/default
nginx -t
systemctl enable nginx
systemctl reload nginx
```

## 14. 创建 systemd 服务

系统一共运行 3 个核心后端服务：

```text
arbitrage-orderbook-data.service   盘口数据服务，维护 Binance/Gate WS，本机端口 19877
arbitrage-orderbook.service        主服务，API + 前端 WS，本机端口 19876
arbitrage-executor.service         虚拟盘成交服务，本机端口 8081
arbitrage-real-executor.service    实盘/测试网成交服务，本机端口 8082
```

虚拟盘只启用 `arbitrage-executor.service`。实盘只启用 `arbitrage-real-executor.service`。

### 14.1 盘口数据服务

```bash
vim /etc/systemd/system/arbitrage-orderbook-data.service
```

写入：

```ini
[Unit]
Description=Arbitrage Orderbook Data Service
After=network-online.target mysql.service
Wants=network-online.target mysql.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/ARBITRAGE-MI/src
EnvironmentFile=/opt/ARBITRAGE-MI/.env
Environment=PATH=/opt/ARBITRAGE-MI/.venv/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
ExecStart=/opt/ARBITRAGE-MI/.venv/bin/python -m api.orderbook_data_service
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

### 14.2 主服务

```bash
vim /etc/systemd/system/arbitrage-orderbook.service
```

写入：

```ini
[Unit]
Description=Arbitrage Orderbook Server
After=network-online.target mysql.service arbitrage-orderbook-data.service
Wants=network-online.target mysql.service arbitrage-orderbook-data.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/ARBITRAGE-MI/src
EnvironmentFile=/opt/ARBITRAGE-MI/.env
Environment=PATH=/opt/ARBITRAGE-MI/.venv/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
ExecStart=/opt/ARBITRAGE-MI/.venv/bin/python -m api.orderbook_server
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

### 14.3 虚拟盘成交服务

```bash
vim /etc/systemd/system/arbitrage-executor.service
```

写入：

```ini
[Unit]
Description=Arbitrage Virtual Executor Service
After=network-online.target mysql.service
Wants=network-online.target mysql.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/ARBITRAGE-MI/src

Environment=PATH=/opt/ARBITRAGE-MI/.venv/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## 21. 常见问题

### apt 提示 Unable to locate package

如果安装基础软件时出现类似下面的错误：

```text
Unable to locate package unzip
Unable to locate package nginx
Package python3-venv has no installation candidate
```

先确认系统是不是 Ubuntu：

```bash
cat /etc/os-release
```

如果不是 `Ubuntu 22.04` 或 `Ubuntu 24.04`，建议直接在阿里云重装系统，镜像选择：

```text
Ubuntu 22.04 LTS x86_64
```

如果显示的是 `Ubuntu 26.04`，也建议重装为 `Ubuntu 22.04 LTS x86_64`。26.04 太新，阿里云软件源和第三方安装脚本可能还没完全适配，容易出现 `python3-venv`、`mysql-server`、`nginx` 等基础包找不到的问题。

如果确认是 Ubuntu，通常是 apt 软件源没有更新或源配置异常，依次执行：

```bash
apt clean
rm -rf /var/lib/apt/lists/*
apt update
```

如果 `apt update` 也报错或仍找不到包，把软件源切到阿里云 Ubuntu 源。Ubuntu 22.04 使用：

```bash
cat > /etc/apt/sources.list <<'EOF'
deb http://mirrors.aliyun.com/ubuntu/ jammy main restricted universe multiverse
deb http://mirrors.aliyun.com/ubuntu/ jammy-security main restricted universe multiverse
deb http://mirrors.aliyun.com/ubuntu/ jammy-updates main restricted universe multiverse
deb http://mirrors.aliyun.com/ubuntu/ jammy-backports main restricted universe multiverse
EOF

apt clean
rm -rf /var/lib/apt/lists/*
apt update
```

Ubuntu 24.04 使用：

```bash
cat > /etc/apt/sources.list <<'EOF'
deb http://mirrors.aliyun.com/ubuntu/ noble main restricted universe multiverse
```

### 前端能打开，但接口报错

检查主服务：

```bash
systemctl status arbitrage-orderbook --no-pager
journalctl -u arbitrage-orderbook -n 100 --no-pager
curl http://127.0.0.1:19876/api/health
```

### 盘口一直没有数据

检查盘口数据服务和交易所连接：

```bash
systemctl status arbitrage-orderbook-data --no-pager
journalctl -u arbitrage-orderbook-data -n 200 --no-pager
curl http://127.0.0.1:19877/api/service/status
```

### 登录失败

确认数据库是从旧环境完整导入的，并且 `mi_users` 表存在：

```bash
mysql -u arb_app -p crypto_arbitrage -e "SELECT id, username FROM mi_users;"
```

### 数据库连接失败

检查 `.env` 与 MySQL 用户：

```bash
cat /opt/ARBITRAGE-MI/.env | grep MYSQL
mysql -u arb_app -p crypto_arbitrage -e "SELECT 1;"
```

### 修改 `.env` 后不生效

systemd 服务需要重启：

```bash
systemctl restart arbitrage-orderbook-data
systemctl restart arbitrage-orderbook
systemctl restart arbitrage-real-executor
```

如果当前是虚拟盘：

```bash
systemctl restart arbitrage-executor
```

### 不要公网开放 MySQL

迁移数据尽量用 `scp` 上传 dump 后本机导入。不要为了 Navicat 长期开 `3306`。如果必须临时开放，导入完成后立即删除安全组规则，并确认 MySQL 只监听本机：

```bash
ss -lntp | grep 3306
```
