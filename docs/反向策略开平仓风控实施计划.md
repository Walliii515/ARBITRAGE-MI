# 反向策略开平仓风控实施计划

本文档用于跟踪反向套利从“只读机会扫描”推进到“完整开仓、平仓、风控、复盘闭环”的实现进度。

反向策略方向：

```text
开仓：Binance Cross Margin 借币卖出现货 + Gate Futures 做多
平仓：Binance Cross Margin 买回现货并还币 + Gate Futures 平多
```

核心原则：

- 正向策略保持不动，反向策略必须独立模块、独立配置、独立账户、独立状态、独立订单与持仓记录。
- 正向可以复用方向无关的底层工具，例如盘口合并、VWAP 计算、交易所客户端、表格组件；任何方向相关判断必须显式传入方向或放在反向专属模块。
- 第一阶段默认 `execution_enabled=false`，先完成信号、旁路、虚拟/只读演练，再打开真实执行。
- 每一步完成后必须补测试，并确认正向核心测试不回归。

## 状态约定

| 状态 | 含义 |
|---|---|
| `todo` | 未开始 |
| `doing` | 开发中 |
| `blocked` | 被依赖或外部条件阻塞 |
| `done` | 已实现、已验证、已合并 |

## 2. 反向开仓执行前置风控

目标：把当前“交易信号观察态”升级成“可进入真实开仓前的完整门禁”，但仍不下实盘单。

| ID | 状态 | 任务 | 设计要点 | 验收标准 |
|---|---|---|---|---|
| R2-1 | todo | 反向开仓配置对象 | `ReverseOpenConfig` 注入金额、覆盖率阈值、边际盈亏阈值、借币策略、FundingCarry、行情延迟阈值 | `calc` 不直接读全局 config |
| R2-2 | todo | 借币容量策略 | 第一版保持“额度不足不开”；不做有多少开多少。后续若要动态降档，必须单独配置 `min_open_amount_usdt` | `borrow_capacity_usdt < open_amount_usdt` 时不进入开仓 |
| R2-3 | todo | 反向开仓 resiliency | 观察 `spot bid + future ask` 盘口恢复、spread、basis 波动、coverage | 通过/拒绝原因写入 `mi_reverse_trade_signal.reject_reason` |
| R2-4 | todo | 反向开仓旁路复核 | 单标的最短链路重新计算：行情延迟、跨所同步、Gate ready、负 funding、借币仍可用、额度仍足、边际盈亏仍 >= 0、coverage 达标 | 旁路失败时 `gate_rejected`，不会进入执行 |
| R2-5 | todo | FundingCarry 旁路一致性 | `funding_carry` 也必须通过借币、coverage、行情延迟、边际盈亏、执行保护 | FundingCarry 只改变形态入口，不绕过风控 |
| R2-6 | todo | 反向冷却与降噪 | 独立维护同标的信号冷却、旁路拒绝冷却、借币失败冷却、执行漂移冷却 | 不共享正向 `TradingExecutor` 的内存状态 |

验证：

- 构造候选标的：满足前置条件后进入 `monitoring`。
- 构造借币不足：不进入交易信号，只在机会扫描展示。
- 构造行情滞后：`gate_rejected`，原因包含 lag/skew。
- 构造 FundingCarry：满足 carry 条件但仍走旁路。

## 3. 反向开仓执行器

目标：实现真实开仓闭环，但先支持 `dry_run` / `virtual`，再开启 live。

| ID | 状态 | 任务 | 设计要点 | 验收标准 |
|---|---|---|---|---|
| R3-1 | todo | 反向 ExecutorClient 边界 | 可以新增 `ReverseExecutorClient` 或方向参数化 executor，但不能在正向 `TradingExecutor` 内塞反向分支 | 反向执行入口独立 |
| R3-2 | todo | Binance Cross Margin 卖出现货 | 支持借币、margin sell，或确认 Binance margin sell 自动借币模式是否满足需求 | 返回借币数量、成交数量、成交金额、手续费 |
| R3-3 | todo | Gate Futures 做多 | 下 buy order，记录 contract、qty、price、fee、reduce_only=false | 与 Binance 腿数量按对冲口径匹配 |
| R3-4 | todo | 开仓失败补偿 | 若一腿成功一腿失败，执行反向 unwind，防止裸 short spot 或裸 long future | 单腿失败不会静默留下裸仓 |
| R3-5 | todo | 开仓持久化 | 写入 reverse order/position/signal，包含 signal/pre_gate/actual 三段基差 | 页面能看到真实 opened 持仓 |
| R3-6 | todo | BNB 手续费与费用折算 | 复用或扩展现有订单费用解析，支持 margin spot 与 Gate future | PnL 不只依赖静态费率 |

验证：

- `execution_enabled=false` 时只记录 ready/observed，不下单。
- `virtual` 模式能产生反向持仓。
- `live` 前先跑小金额手动白名单标的。
- 正向真实执行器 `/api/connectivity` 仍使用 forward 账户。

## 4. 反向持仓监控与 PnL

目标：建立反向持仓的实时收益、借币成本、资金费收益和风险状态。

| ID | 状态 | 任务 | 设计要点 | 验收标准 |
|---|---|---|---|---|
| R4-1 | todo | 反向持仓实时 PnL | `basis_profit_bps = reverse_close_basis_bps - reverse_open_basis_bps` | 持仓页显示当前可平仓收益 |
| R4-2 | todo | 资金费记录 | Gate long future 在负 funding 时收钱，转正时付钱 | 每次 funding 入账后更新 reverse position |
| R4-3 | todo | 借币利息记录 | 记录 hourly rate、累计利息、利率变化 | PnL 扣除真实或估算借币成本 |
| R4-4 | todo | Margin Level 风控 | 监控 Binance Cross Margin marginLevel、借币资产、抵押资产 | marginLevel 低于阈值时进入风险状态 |
| R4-5 | todo | Gate Long 风控 | 监控 Gate long futures 保证金、强平价、ADL 风险 | 低于阈值时风险平仓或补保证金 |

验证：

- 一条反向持仓能实时显示 basis、funding、borrow、fee、net pnl。
- Cross Margin 与 Gate 风险字段刷新不影响正向持仓监控。

## 5. 反向平仓逻辑

目标：实现反向策略真正的退出闭环。

| ID | 状态 | 任务 | 设计要点 | 验收标准 |
|---|---|---|---|---|
| R5-1 | todo | 反向止盈公式 | `net_profit_bps = reverse_close_basis_bps - reverse_open_basis_bps + funding_pnl_bps - borrow_cost_bps - fee_full_bps` | 达到阈值才进入平仓监控 |
| R5-2 | todo | 顶部回落确认 | 反向平仓基差越高越好，止盈达标后等待见顶，回落固定比例或超时再平 | 不套用正向 valley 公式 |
| R5-3 | todo | 反向 close resiliency | 观察 `spot ask + future bid` 盘口恢复、spread、basis 波动、coverage | 盘口差时等待或拒绝 |
| R5-4 | todo | 反向平仓旁路 | 下单前重新校验行情延迟、跨所同步、Gate ready、净收益、coverage、可买回/可还币路径 | 失败写详细 close reject reason |
| R5-5 | todo | 平仓执行 | Binance Cross Margin buy 回补借币 + Gate future sell reduce-only 平多 + repay | 成功后 position=closed |
| R5-6 | todo | 还币失败处理 | 买回成功但 repay 失败时，记录风险状态并报警；不得误标完全 closed | 可人工恢复，复盘清晰 |
| R5-7 | todo | 手动平仓 | 先支持单个反向持仓手动平仓，再支持自动止盈 | 手动入口仍走行情延迟和 reduce-only 保护 |

验证：

- 反向持仓能从 holding 到 closed。
- 平仓订单包含 spot buy、future sell、repay 结果。
- close_reason 能解释：止盈、Funding 风险、保证金风险、手动、旁路拒绝。

## 6. 反向风险退出

目标：处理不是止盈但必须退出的场景。

| ID | 状态 | 任务 | 设计要点 | 验收标准 |
|---|---|---|---|---|
| R6-1 | todo | Funding 转正风险 | 如果 funding 转正且临近结算/极端恶化/累计已付超阈值，触发风险平仓 | 风险平仓可 `require_profit=false` |
| R6-2 | todo | 借币利率飙升 | 借币 hourly rate 超阈值或 borrowable 变 false，触发风险评估 | 记录 borrow risk reason |
| R6-3 | todo | Binance Cross Margin 风险 | marginLevel 低于阈值时触发补抵押或风险平仓 | 不与正向 Gate 保证金逻辑混用 |
| R6-4 | todo | Gate ADL/强平事件 | 监听/识别 Gate long future 的 ADL/强平，标记 reverse desynced | 反向 ADL 不阻断正向开仓，除非同账户层面风险 |
| R6-5 | todo | 断腿恢复 | Gate 腿丢失时处理 Binance short spot/借币腿；Binance 腿异常时处理 Gate long | 恢复动作写入 risk event 和 position detail |

验证：

- 构造 funding 转正风险，持仓进入 risk close。
- 构造 Gate 仓位缺失，对账能标记 reverse desynced。
- 风险事件不污染正向 `mi_trade_position`。

## 9. 实施顺序

建议按以下顺序推进，每一阶段合并后再进入下一阶段：

| 顺序 | 阶段 | 目标 | 是否可上生产 |
|---|---|---|---|
| 1 | R1 数据模型 | 建表、API 边界、配置命名空间 | 可以，默认不执行 |
| 2 | R2 开仓前置风控 | 完整 ready-to-open 但不下单 | 可以，观察信号 |
| 3 | R3 虚拟开仓 | virtual/dry-run 完整开仓 | 可以，真实执行关闭 |
| 4 | R4 持仓监控 | PnL、funding、borrow、margin 风险可视 | 可以 |
| 5 | R5 虚拟平仓 | virtual/dry-run 完整平仓 | 可以，真实执行关闭 |
| 6 | R6 风险退出 | funding、借币、margin、ADL 风控 | 谨慎 |
| 7 | R7 前端与对账 | 可观察、可人工干预 | 可以 |
| 8 | R8 小金额 live | 单标的小金额真实开平仓 | 需人工确认 |

## 10. 当前不做的事项

- 不把反向逻辑塞进正向 `TradingExecutor` / `ClosingExecutor` 的分支里。
- 不在借币额度不足时自动“有多少开多少”；第一版统一要求 `borrow_capacity_usdt >= open_amount_usdt`。
- 不复用正向持仓表解释反向仓位，除非先完成显式 `strategy` 字段改造和全链路查询隔离。
- 不因为反向上线而修改正向订阅数量、正向账户、正向开仓阈值、正向平仓阈值。
- 不在真实执行开启前跳过 virtual/dry-run 和只读 API 校验。
