# 交易逻辑说明

## 策略概述

跨交易所资金费率套利策略：在 Binance 现货买入 + Gate 永续合约做空，赚取正资金费率收入，同时在基差收敛时止盈。

---

## 开仓逻辑

**入口**: `src/calc/trading_executor.py` → `TradingExecutor.check_and_open()`

**触发频率**: 每 5 秒检查一次（`trade.open_check_interval_sec`）

### 风控条件（全部通过才开仓）

| # | 条件 | 配置项 | 默认值 | 说明 |
|---|------|--------|--------|------|
| 1 | 资金费率 >= 阈值 | `trade.funding_rate_threshold_percentile` | percentile_30 | 24h资金费率需达到该标的历史分位水平 |
| 2 | 开仓盘口覆盖 <= 阈值 | `trade.orderbook_coverage_threshold` | 0.8 | 流动性充足（覆盖率越低说明盘口越厚） |
| 3 | 开仓VWAP基差 >= 阈值 | `trade.vwap_open_threshold_percentile` | open_basis_p20 | 基差需处于历史高位（按标的动态阈值，无记录时回退全局阈值） |
| 4 | **盈利性守卫** | `trade.vwap_close_threshold_percentile` | close_basis_p20 | 开仓基差 > 平仓基差阈值 + 手续费 |

### 盈利性守卫（新增）

**公式**: `open_vwap_basis_bps > close_basis_threshold + fee_cost_bps`

**含义**: 确保开仓时的基差高于预期平仓时的基差 + 手续费成本，只有价差存在收敛空间时才允许开仓。

**作用**: 自动过滤因跨所买卖价差过大导致的"结构性亏损"标的（如 open_basis_max < close_basis_min 的情况）。

**数据来源**: `mi_vwap_basis_threshold` 表，每日自动重算，无需手动配置。

### 其他条件

- **冷却期**: 同一标的 1 小时内不重复开仓（`trade.open_cooldown_sec: 3600`）

### 峰值回落 确认

风控条件全部通过后，不会立即开仓，而是进入“峰值监控”状态：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `trade.peak_pullback_pct` | 0.10 | 从峰值回落 10% 确认开仓 |
| `trade.peak_monitor_timeout_sec` | 60 | 监控超时(秒)，超时后直接开仓 |

**状态机流程**:
```
基差 < 阈值          → 不开仓，无状态
基差 >= 阈值(首次)  → 开始监控，记录峰值和开始时间
基差继续上升       → 更新峰值，继续等待
基差回落 >= 10%      → 确认开仓
等待超过 60s        → 直接开仓（保底）
基差跌回阈值下      → 清除状态，放弃本轮
```

**举例**（阈值=50bps, pullback=10%）:
- 基差: 40→50(开始监控)→60→75(峰值)→67.5(75×0.9=67.5, 回落10%) → **开仓于 67.5 bps**
- 对比无峰值确认: 开仓于 50 bps，多捕获 17.5 bps 收敛空间

### 开仓操作

1. 现货: 买入（ask 侧 VWAP）
2. 期货: 做空（bid 侧 VWAP）
3. 金额: `trade.open_amount_usdt`（默认 500 USDT）

**VWAP计算说明**:
- VWAP（Volume Weighted Average Price）是市价单真实成交均价
- 市价单按盘口逐档成交，VWAP是加权平均价的计算结果
- **VWAP不需要满足交易所tick_size规则**（那是限价单的要求）
- 例如：VWAP可能=0.011655，这是真实成交均价，不是提交的限价
- 基差计算使用VWAP的真实精度，不做floor截断

## 平仓逻辑

**入口**: `src/calc/closing_executor.py` → `ClosingExecutor.check_and_close()`

**触发频率**: 每 5 秒检查一次（`trade.close_check_interval_sec`）

### 平仓条件（按优先级，命中即平仓）

#### 条件 1: 资金费次数平仓

| 字段 | 说明 |
|------|------|
| 触发条件 | `funding_payments_count >= max_funding_payments` |
| 配置项 | `trade.max_funding_payments: 30` |
| 含义 | 持仓时间过长（30次 × 8小时 = 10天），强制平仓 |

#### 条件 2: 止盈平仓

| 字段 | 说明 |
|------|------|
| 触发条件 | `total_pnl_bps >= funding_rate_bps × multiplier + fee_cost_bps` |
| 配置项 | `trade.take_profit_days_multiplier: 10` |
| 含义 | 总盈亏（基差收敛 + 已收资金费）达到 N 天资金费等价收益 + 手续费 |

**公式展开**:
```
spread_profit_bps = open_spread_bps - current_spread_bps     (基差收敛利润)
funding_earned_bps = funding_total_pnl / open_amount * 10000  (已实现资金费收益 bps)
total_pnl_bps = spread_profit_bps + funding_earned_bps       (总盈亏)

funding_rate_bps = funding_rate_24h × 10000                   (24h费率转 bps)
fee_cost_bps = (spot_open + spot_close + future_open + future_close) × 10000  (默认 30bps)
threshold = funding_rate_bps × multiplier + fee_cost_bps      (如 3×10+30=60bps)

触发: total_pnl_bps >= threshold
```

**参数说明**:
- `take_profit_days_multiplier = 10` 作用于 **24小时资金费率**，即止盈目标 = 10天的资金费收入
- 资金费每8小时结算一次（24h费率 = 3次单次费率），N=10 对应 30 次资金费支付

**举例**（funding_rate_24h=0.0003→ 3bps/天, multiplier=10, 费率=30bps）:
- 阈值 = 3×10 + 30 = **60 bps**
- 场景 A: 开仓基差 80bps，当前基差 40bps，已收资金费 25bps → 总盈亏 = 40+25 = 65 >= 60 → **触发止盈**
- 场景 B: 开仓基差 80bps，当前基差 60bps，已收资金费 5bps → 总盈亏 = 20+5 = 25 < 60 → 不触发

**前提**: 仅在资金费率 > 0 时适用。

### 谷底反弹确认（止盈专用）

止盈条件首次满足后，不会立即平仓，而是进入“谷底监控”状态：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `trade.valley_rebound_pct` | 0.10 | 从谷底反弹收敛范围的10%确认平仓 |
| `trade.valley_monitor_timeout_sec` | 60 | 监控超时(秒)，超时后直接平仓 |

**状态机流程**:
```
止盈未满足          → 不平仓，无状态
止盈满足(首次)     → 开始监控，记录当前spread为谷底
spread继续下降       → 更新谷底，继续等待（收敛还在继续）
spread反弹 >= 10%    → 确认平仓（收敛已见底）
等待超过 60s        → 直接平仓（保底）
止盈不再满足       → 清除状态，放弃本轮
```

**反弹计算方式**:
```
收敛范围 = 开仓基差 - 谷底基差
反弹阈值 = 谷底基差 + 收敛范围 × rebound_pct
触发: current_spread_bps >= 反弹阈值
```

**举例**（开仓基差=80bps, 谷底=10bps, rebound=10%）:
- 收敛范围 = 80-10 = 70bps
- 反弹阈值 = 10 + 70×0.10 = **17 bps**
- 基差: 80→止盈触发(开始监控)→30→20→10(谷底)→17(反弹确认) → **平仓于 17 bps**
- 对比无谷底确认: 平仓于 30 bps，多捕捉 13 bps 收敛利润

#### 条件 3: 资金费率为负平仓

当资金费率转负时（我们在亏钱），根据距下次结算的时间动态选择平仓阈值：

| 剩余时间 | 使用阈值 | 宽松度 |
|---------|---------|--------|
| > 3 小时 | close_basis_p10 | 最严格（只在基差很低时才平） |
| 2~3 小时 | close_basis_p20 | |
| 1~2 小时 | close_basis_p30 | |
| 15分钟~1小时 | close_basis_p40 | 较宽松 |
| ≤ 15 分钟 | 无条件平仓 | 必须平仓，避免支付负费率 |

**触发条件**: `current_spread_bps <= close_basis_pX`（当前基差已收敛到历史低位）

### 平仓操作

1. 现货: 卖出（bid 侧 VWAP）
2. 期货: 买入平仓（ask 侧 VWAP）

## 数据流

```
订单簿 WebSocket (Binance现货 + Gate期货)
    ↓
合并订单簿 → 计算对冲指标(VWAP/覆盖率)
    ↓
┌─────────────────────────────────────────┐
│ 开仓循环 (每5秒)                          │
│  1. 资金费率 >= 阈值?                      │
│  2. 盘口覆盖 <= 0.8?                      │
│  3. VWAP基差 >= open_basis_p20?           │
│  4. 盈利性守卫: 基差 > 平仓阈值 + 手续费?    │
│  5. 冷却期已过?                            │
│  6. 峰值回落确认(回落10%或超时60s)?       │
│  → 通过: 调用成交引擎开仓                   │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│ 平仓循环 (每5秒)                          │
│  优先级1: 资金费次数 >= 30? → 直接平仓    │
│  优先级2: 总盈亏 >= N天资金费+手续费?         │
│    → 谷底反弹确认(反弹10%或超时60s)      │
│  优先级3: 费率为负 → 按时间梯度平仓           │
│  → 触发: 调用成交引擎平仓                   │
└─────────────────────────────────────────┘
```

## 核心配置项一览

| 配置路径 | 默认值 | 说明 |
|---------|--------|------|
| `trade.open_amount_usdt` | 500 | 每次开仓金额(USDT) |
| `trade.open_check_interval_sec` | 5 | 开仓检查间隔(秒) |
| `trade.close_check_interval_sec` | 5 | 平仓检查间隔(秒) |
| `trade.open_cooldown_sec` | 3600 | 同标的开仓冷却(秒) |
| `trade.orderbook_coverage_threshold` | 0.8 | 盘口覆盖上限 |
| `trade.vwap_open_threshold_percentile` | open_basis_p20 | 开仓基差分位阈值列(按标的) |
| `trade.open_vwap_basis_threshold_bps` | 20 | 无标的阈值时的全局回退基差阈值(bps) |
| `trade.vwap_close_threshold_percentile` | close_basis_p20 | 平仓基差分位阈值列 |
| `trade.funding_rate_threshold_percentile` | percentile_30 | 资金费率分位阈值列 |
| `trade.take_profit_days_multiplier` | 10 | 止盈倍数(等价N天资金费) |
| `trade.max_funding_payments` | 30 | 最大资金费支付次数 |
| `trade.peak_pullback_pct` | 0.10 | 峰值回落确认比例(10%) |
| `trade.peak_monitor_timeout_sec` | 60 | 峰值监控超时(秒) |
| `trade.valley_rebound_pct` | 0.10 | 谷底反弹确认比例(10%收敛范围) |
| `trade.valley_monitor_timeout_sec` | 60 | 谷底监控超时(秒) |
| `trade.fee.spot_open` | 0.00075 | 现货开仓手续费率 |
| `trade.fee.spot_close` | 0.00075 | 现货平仓手续费率 |
| `trade.fee.future_open` | 0.00075 | 期货开仓手续费率 |
| `trade.fee.future_close` | 0.00075 | 期货平仓手续费率 |
| `trade.executor.url` | http://localhost:8081 | 成交引擎服务地址 |

## 关键数据表

| 表名 | 用途 |
|------|------|
| `mi_vwap_basis_threshold` | 按标的VWAP基差分位阈值（每日重算） |
| `mi_gate_future_funding_rate_threshold` | 资金费率历史分位阈值 |
| `mi_trade_position` | 持仓记录（开仓/平仓状态） |
| `mi_trade_order` | 交易订单记录（开仓/平仓订单） |
| `mi_vwap_basis_snapshot` | VWAP基差快照（用于阈值统计） |
