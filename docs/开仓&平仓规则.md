# 交易逻辑说明

## 策略概述

跨交易所资金费率套利策略：在 Binance 现货买入 + Gate 永续合约做空，赚取正资金费率收入，同时在基差收敛时止盈。

---

## 保证金风控体系

**模式**: 逐仓保证金（Isolated Margin）

**核心优势**: 每个合约仓位独立计算保证金和爆仓风险，一个仓位爆仓不会影响其他仓位或现货资产，实现风险隔离。

### 爆仓价计算

**入口**: `src/calc/position_pnl_calculator.py` → `calculate_realtime_pnl()`

**公式**（逐仓空头）:
```
liq_price = future_open_price × (1 + 1/leverage - maintenance_rate)
```

**参数说明**:
| 参数 | 来源 | 默认值 | 说明 |
|------|------|--------|------|
| `future_open_price` | 开仓时期货VWAP成交价 | - | 持仓记录中的 `future_open_price` |
| `leverage` | `margin.leverage` | 2 | 杠杆倍数 |
| `maintenance_rate` | `mi_gate_future_contracts.maintenance_rate` | 0.005 | 维持保证金率（优先用交易所值，缺失时回退 `margin.default_maintenance_rate`） |

**举例**（leverage=2, maintenance_rate=0.005, 开仓价=100）:
```
liq_price = 100 × (1 + 1/2 - 0.005) = 100 × 1.495 = 149.5
```
含义：期货价格涨到 149.5 时触发爆仓（空头方向，价格上涨=亏损）。

### 距爆仓距离

**公式**:
```
liq_distance_pct = (liq_price - current_future_price) / current_future_price × 100
```

**状态划分**:
| 距爆仓距离 | 状态 | 系统行为 |
|-----------|------|----------|
| > 5%（`warning_pct`） | 正常 | 允许开仓/持仓 |
| < 5%（`close_threshold_pct`） | 危险 | 禁止开仓 + 触发紧急平仓（最高优先级） |
| ≤ 0% | 模拟爆仓 | 触发紧急平仓 |

### 三层风控设计

```
┌────────────────────────────────────────────────────┐
│  第1层：预防性风控（开仓阶段）                         │
│  - 距爆仓距离 < warning_pct(5%) → 禁止加仓          │
│  - 同标的持仓数 >= max_positions_per_asset → 禁止    │
├────────────────────────────────────────────────────┤
│  第2层：监控性风控（持仓期间）                         │
│  - 每5秒实时计算爆仓价和距爆仓距离                     │
│  - 推送到前端持仓监控页面展示                          │
├────────────────────────────────────────────────────┤
│  第3层：应急性风控（平仓阶段，优先级0）                  │
│  - 距爆仓距离 < close_threshold_pct(5%) → 紧急平仓   │
│  - 不受平仓冷却期限制，不受谷底监控影响                  │
└────────────────────────────────────────────────────┘
```

### 风险隔离说明

由于采用逐仓模式：
- 每个标的的期货仓位使用**独立保证金**，爆仓仅影响该仓位本身
- 现货仓位不受期货爆仓影响（现货在 Binance，期货在 Gate，物理隔离）
- 系统在爆仓**之前**（距离 5%）主动平仓，避免真实爆仓发生
- 即使系统平仓失败导致真实爆仓，损失也仅限于该仓位的保证金（开仓金额/杠杆）

**最大单仓损失**:
```
max_loss = open_amount_usdt / leverage = 100 / 2 = 50 USDT
```
即使爆仓，单个仓位最大损失为 50 USDT（保证金全部亏光）。

### 保证金配置项

| 配置路径 | 默认值 | 说明 |
|---------|--------|------|
| `margin.leverage` | 2 | 杠杆倍数（初始保证金 = 名义价值/杠杆） |
| `margin.default_maintenance_rate` | 0.005 | 默认维持保证金率（0.5%） |
| `margin.warning_pct` | 5 | 预警阈值(%)：低于此值禁止开仓 |
| `margin.close_threshold_pct` | 5 | 平仓阈值(%)：低于此值紧急平仓 |

## 开仓逻辑

**入口**: `src/calc/trading_executor.py` → `TradingExecutor.check_and_open()`

**触发频率**: 每 0.5 秒检查一次（`trade.open.check_interval_sec`）

### 风控条件（全部通过才开仓）

| # | 条件 | 配置项 | 默认值 | 说明 |
|---|------|--------|--------|------|
| 0 | 同标的持仓数 < 上限 | `trade.max_positions_per_asset` | 5 | 防止同一波行情连续开仓 |
| 0.5 | **保证金风控** | `margin.warning_pct` | 5 | 该标的现有持仓距爆仓距离 >= 5% |
| 1 | 资金费率 >= -15bps | `trade.open.min_funding_rate_bps` | -15 | 24h资金费率不低于此下限（bps），过滤深度负费率标的 |
| 2 | 开仓盘口覆盖 <= 阈值 | `trade.orderbook_coverage_threshold` | 0.6 | 流动性充足（覆盖率越低说明盘口越厚） |
| 3 | 开仓VWAP基差 >= p20 + 回落确认，或 >= p10 直接开仓 | `mi_vwap_basis_threshold` | open_basis_p10/p20 | 高基差(p10)直接开，中高基差(p20)需回落确认 |
| 4 | **盈利性守卫** | `trade.vwap_close_threshold_percentile` | close_basis_p20 | 开仓基差 > 平仓基差阈值 + 手续费 |
| 5 | 期货24h成交量 >= 阈值 | `trade.min_future_volume_24h_usdt` | 50000 | 期货流动性过滤 |
| 6 | 现货24h成交量 >= 阈值 | `trade.min_spot_volume_24h_usdt` | 100000 | 现货流动性过滤 |

### 保证金风控（开仓阶段）

**逻辑**: 每个开仓检查周期前，系统遍历所有 holding 状态的持仓，按标的聚合最小距爆仓距离。

**检查规则**:
- 若该标的存在持仓且最小 `liq_distance_pct < margin.warning_pct(5%)`，禁止该标的继续开仓
- 同一标的多个仓位时，取最危险的（距爆仓距离最小的）进行判断

**作用**: 防止在价格已经大幅不利的情况下继续加仓，避免保证金压力累积。

### 盈利性守卫

**公式**: `open_vwap_basis_bps > close_basis_threshold + fee_cost_bps`

**含义**: 确保开仓时的基差高于预期平仓时的基差 + 手续费成本，只有价差存在收敛空间时才允许开仓。

**作用**: 自动过滤因跨所买卖价差过大导致的"结构性亏损"标的（如 open_basis_max < close_basis_min 的情况）。

**数据来源**: `mi_vwap_basis_threshold` 表，每日自动重算，无需手动配置。

### 其他条件

- **冷却期**: 同一标的开仓后短期内不重复开仓（`trade.open_cooldown_sec: 15`）

### 峰值回落确认

风控条件全部通过后，不会立即开仓，而是进入"峰值监控"状态：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `trade.pullback_pct` | 0.05 | 从峰值回落 5% 确认开仓 |
| `trade.peak_monitor_timeout_sec` | 60 | 监控超时(秒)，超时后直接开仓 |
| `trade.peak_timeout_cooldown_sec` | 300 | 超时开仓后的冷却期(秒)，防止连续超时重复开仓 |

**状态机流程**:
```
基差 < 阈值          → 不开仓，无状态
基差 >= 阈值(首次)  → 开始监控，记录峰值和开始时间
基差继续上升       → 更新峰值，继续等待
基差回落 >= 10%      → 确认开仓
等待超过 60s        → 直接开仓（保底），并进入300s超时冷却期
基差跌回阈值下      → 清除状态，放弃本轮
数据不完整(盘口中断) → 清除状态，避免恢复后误触发
```

**举例**（阈值=50bps, pullback=10%）:
- 基差: 40→50(开始监控)→60→75(峰值)→67.5(75×0.9=67.5, 回落10%) → **开仓于 67.5 bps**
- 对比无峰值确认: 开仓于 50 bps，多捕获 17.5 bps 收敛空间

### 开仓操作

1. 现货: 买入（ask 侧 VWAP）
2. 期货: 做空（bid 侧 VWAP）
3. 金额: `trade.open_amount_usdt`（默认 100 USDT）

**VWAP计算说明**:
- VWAP（Volume Weighted Average Price）是市价单真实成交均价
- 市价单按盘口逐档成交，VWAP是加权平均价的计算结果
- **VWAP不需要满足交易所tick_size规则**（那是限价单的要求）
- 例如：VWAP可能=0.011655，这是真实成交均价，不是提交的限价
- 基差计算使用VWAP的真实精度，不做floor截断

## 平仓逻辑

**入口**: `src/calc/closing_executor.py` → `ClosingExecutor.check_and_close()`

**触发频率**: 每 0.5 秒检查一次（`trade.close.check_interval_sec`）

### 平仓条件（按优先级，命中即平仓）

#### 条件 0: 保证金爆仓风控（最高优先级）

| 字段 | 说明 |
|------|------|
| 触发条件 | `liq_distance_pct < margin.close_threshold_pct` |
| 配置项 | `margin.close_threshold_pct: 5` |
| 含义 | 距爆仓距离不足 5%，紧急两端同时平仓 |
| 特殊处理 | 不受平仓冷却期限制；清除谷底反弹监控状态 |

**触发场景**: 期货价格大幅上涨（做空方向亏损），导致仓位接近爆仓价。

**平仓原因记录**:
```
保证金风控|距爆仓{X}%(<5%)|爆仓价{liq_price}|当前{current_price}
```

#### 条件 1: 资金费次数平仓

| 字段 | 说明 |
|------|------|
| 触发条件 | `funding_payments_count >= max_funding_payments` |
| 配置项 | `trade.max_funding_payments: 30` |
| 含义 | 持仓时间过长（30次 × 8小时 = 10天），强制平仓 |

#### 条件 2: 止盈平仓

| 字段 | 说明 |
|------|------|
| 触发条件 | `total_pnl_bps >= funding_rate_p40_bps × multiplier + fee_cost_bps` |
| 配置项 | `trade.take_profit_days_multiplier: 10` |
| 费率来源 | `mi_gate_future_funding_rate_threshold.percentile_40`（约为中位数正资金费率） |
| 含义 | 总盈亏（基差收敛 + 已收资金费）达到 10 天历史中位费率等价收益 + 手续费 |

**公式展开**:
```
spread_profit_bps = open_spread_bps - current_spread_bps     (基差收敛利润)
funding_earned_bps = funding_total_pnl / open_amount * 10000  (已实现资金费收益 bps)
total_pnl_bps = spread_profit_bps + funding_earned_bps       (总盈亏)

funding_rate_p40_bps = percentile_40 × 10000                  (历史p40费率转 bps)
fee_cost_bps = (spot_open + spot_close + future_open + future_close) × 10000  (默认 30bps)
threshold = funding_rate_p40_bps × multiplier + fee_cost_bps  (如 3×10+30=60bps)

触发: total_pnl_bps >= threshold
```

**参数说明**:
- `take_profit_days_multiplier = 10` 作用于 **历史 percentile_40 资金费率**，即止盈目标 = 10天的中位费率收入
- 使用历史分位值而非实时费率，确保当前费率为负时止盈仍能正常触发

**举例**（percentile_40=0.0003→ 3bps/天, multiplier=10, 手续费=30bps）:
- 阈值 = 3×10 + 30 = **60 bps**
- 场景 A: 开仓基差 100bps，当前基差 40bps，已收资金费 25bps → 总盈亏 = 60+25 = 85 >= 60 → **触发止盈**
- 场景 B: 开仓基差 80bps，当前基差 60bps，已收资金费 5bps → 总盈亏 = 20+5 = 25 < 60 → 不触发

**说明**: 无论当前资金费率正负，止盈阈值始终基于历史中位数计算，不受实时费率波动影响。

### 谷底反弹确认（止盈专用）

止盈条件首次满足后，不会立即平仓，而是进入"谷底监控"状态：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `trade.valley_rebound_pct` | 0.10 | 从谷底反弹收敛范围的10%确认平仓 |
| `trade.valley_monitor_timeout_sec` | 60 | 监控超时(秒)，超时后直接平仓 |

**状态机流程**:
```
止盈未满足          → 不平仓，无状态
止盈满足(首次)     → 开始监控，记录当前spread为谷底
spread继续下降       → 更新谷底，继续等待（收敛还在继续）
spread反弹 >= 10%    → 确认平仓（收敛已见底）
等待超过 60s        → 直接平仓（保底）
止盈不再满足       → 清除状态，放弃本轮
```

**反弹计算方式**:
```
收敛范围 = 开仓基差 - 谷底基差
反弹阈值 = 谷底基差 + 收敛范围 × rebound_pct
触发: current_spread_bps >= 反弹阈值
```

**举例**（开仓基差=80bps, 谷底=10bps, rebound=10%）:
- 收敛范围 = 80-10 = 70bps
- 反弹阈值 = 10 + 70×0.10 = **17 bps**
- 基差: 80→止盈触发(开始监控)→30→20→10(谷底)→17(反弹确认) → **平仓于 17 bps**
- 对比无谷底确认: 平仓于 30 bps，多捕捉 13 bps 收敛利润

#### 条件 3: 累计资金费支出超阈值平仓

当资金费率转负时，不再按时间梯度强平，而是看累计支出是否侵蚀了预期收益空间：

| 字段 | 说明 |
|------|------|
| 前置条件 | `funding_rate_24h < 0`（当前费率为负时才检查） |
| 触发条件 | `abs(funding_pnl_bps) >= max(open_basis_p20 - close_basis_p20, 15) × 0.5` |
| 配置项 | `trade.close.funding_cost_tolerance_ratio: 0.5` |
| 保底值 | `trade.close.funding_cost_min_threshold_bps: 15` |
| 含义 | 累计资金费净支出吃掉了预期基差收敛空间的50%，继续持有已不划算 |

**公式展开**:
```
convergence_space = open_basis_p20 - close_basis_p20   (预期基差收敛空间)
effective_space = max(convergence_space, 15)           (保底值防倒挂)
threshold = effective_space × 0.5                      (容忍比例)

触发: abs(funding_pnl_bps) >= threshold
```

**设计理由**:
- 资金费率经常短暂翻负后回正，不应因单次负费率就强平
- 单次资金费支出（几bps）远小于基差扩大造成的亏损（几十bps）
- 只有当累计支出真正威胁到预期利润时才平仓，避免“小费率换大基差亏损”

**举例**（open_basis_p20=60bps, close_basis_p20=20bps）:
- 收敛空间 = 60-20 = 40bps
- 阈值 = 40×0.5 = **20bps**
- 累计资金费支出-25bps（abs=25 >= 20）→ **触发平仓**
- 累计资金费支出-8bps（abs=8 < 20）→ 不触发，继续持有

### 平仓操作

1. 现货: 卖出（bid 侧 VWAP）
2. 期货: 买入平仓（ask 侧 VWAP）

### 平仓失败处理

- 平仓失败后进入冷却期（`trade.close_cooldown_sec: 60`），同一标的 60 秒内不重试
- **例外**: 保证金爆仓风控平仓不受冷却期限制（每轮都会检查）
- 平仓成功后自动清除冷却记录和谷底监控状态

## 数据流

```
订单簿 WebSocket (Binance现货 + Gate期货)
    ↓
合并订单簿 → 计算对冲指标(VWAP/覆盖率)
    ↓
┌──────────────────────────────────────────────┐
│ 实时盈亏计算 (每5秒)                            │
│  - 计算浮动盈亏、资金费收益、总盈亏               │
│  - 计算爆仓价 + 距爆仓距离 (逐仓模式)            │
│  - 推送到前端 + 缓存供风控使用                    │
└──────────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────────┐
│ 开仓循环 (每0.5秒)                               │
│  0. 同标的持仓数 < 上限?                        │
│  0.5 保证金风控: 距爆仓距离 >= 5%?              │
│  1. 资金费率 >= 阈值?                           │
│  2. 盘口覆盖 <= 0.8?                           │
│  3. VWAP基差 >= open_basis_p20?                │
│  4. 盈利性守卫: 基差 > 平仓阈值 + 手续费?        │
│  5. 期货/现货成交量 >= 阈值?                     │
│  6. 冷却期已过?                                 │
│  7. 峰值回落确认(回落10%或超时60s)?             │
│  → 通过: 调用成交引擎开仓                        │
└──────────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────────┐
│ 平仓循环 (每0.5秒)                               │
│  优先级0: 保证金风控 距爆仓<5%? → 紧急平仓      │
│  优先级1: 资金费次数 >= 30? → 直接平仓           │
│  优先级2: 总盈亏 >= N天资金费+手续费?            │
│    → 谷底反弹确认(反弹10%或超时60s)             │
│  优先级3: 累计资金费支出超阈值? → 平仓        │
│  → 触发: 调用成交引擎平仓                        │
└──────────────────────────────────────────────┘
```

## 核心配置项一览

### 交易配置

| 配置路径 | 默认值 | 说明 |
|---------|--------|------|
| `trade.open_amount_usdt` | 100 | 每次开仓金额(USDT) |
| `trade.open.check_interval_sec` | 0.5 | 开仓检查间隔(秒) |
| `trade.close.check_interval_sec` | 0.5 | 平仓检查间隔(秒) |
| `trade.open_cooldown_sec` | 15 | 同标的开仓冷却(秒) |
| `trade.max_positions_per_asset` | 3 | 同标的最大持仓数 |
| `trade.orderbook_coverage_threshold` | 0.8 | 盘口覆盖上限 |
| `trade.vwap_open_threshold_percentile` | open_basis_p20 | 开仓基差分位阈值列(按标的) |
| `trade.open_vwap_basis_threshold_bps` | 20 | 无标的阈值时的全局回退基差阈值(bps) |
| `trade.vwap_close_threshold_percentile` | close_basis_p20 | 平仓基差分位阈值列 |
| `trade.funding_rate_threshold_percentile` | percentile_30 | 资金费率分位阈值列 |
| `trade.min_spot_volume_24h_usdt` | 100000 | 现货24h最低成交额(USDT) |
| `trade.min_future_volume_24h_usdt` | 50000 | 期货24h最低成交额(USDT) |
| `trade.take_profit_days_multiplier` | 15 | 止盈倍数(等价N天资金费) |
| `trade.max_funding_payments` | 30 | 最大资金费支付次数 |
| `trade.peak_pullback_pct` | 0.10 | 峰值回落确认比例(10%) |
| `trade.peak_monitor_timeout_sec` | 60 | 峰值监控超时(秒) |
