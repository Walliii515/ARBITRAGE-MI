# 微量现货残差退出改造计划

## 目标与范围

第一阶段恢复可解释微量现货残差对应仓位的退出资格，不改变数量、历史成交、成本或收益口径。优先复用现有持仓、成交账本、币种减仓锁、对账快照和尘埃兑换队列。正向 Gate 保持全仓，任何处置只减仓。

REZ 回归案例：持仓 647 的一次 Gate 平仓成交 3360，Binance 成交 3359.9，剩余现货 20980.1、期货 20980；币种合计现货 31270.1、期货 31270。差额 0.1 必须持续记账，不能伪造卖出。

## 实施步骤

- [x] 统一微量现货残差判定：有限正数、仅现货多余、双边本地分别与交易所一致、未锁定余额；残差不超过 1 USDT 且不超过对冲数量 1bps，且低于最小独立卖出名义金额。使用 Decimal，阈值不以页面的一张合约容差为准。
- [x] 对账恢复：连续两轮 120 秒内快照、币种锁、数据库行锁、5 秒内双边实仓复核；逐笔核对合约乘数及真实成交剩余。存在未知订单、未解决 ADL/强平或其他执行风险时拒绝恢复。
- [x] 新增可识别的“已核验微量现货残差”风险类型，使用现有状态字段；保留说明及实际数量。保持该币种新开仓阻断，仅恢复退出判断。
- [x] 下单前重新核验：不能只相信持久化标记。仓位、成交账本、余额或阈值变化时禁止下单，交回对账。正常/手动/负费/MMR 平仓共用执行入口。
- [x] 保留原逐笔成交分配与 Gate reduce-only。检查数量切片浮点误差；已成交数量严格用于剩余量持久化。部分成交重新对账，不能跳过后续真实断腿。
- [x] 复用已有平仓后尘埃队列；同币种仍有正常仓位时禁止整币兑换。保留现有资金及收益口径，不在本次重算历史收益。
- [x] 对账和持仓界面显示残差，禁止继续用无说明的“一致”掩盖差额。保留阻断原因和核验日志；残差恢复核验原因随对账快照保存，下单前失败返回具体原因。
- [x] 回归测试、全量测试及前端构建：1045 项测试、17 项子测试通过，前端类型检查及生产构建通过。
- [x] 发布前架构审计、只读线上 REZ 回放；通过后部署，核对自动状态变化与余额。

## 验收矩阵

1. REZ 可解释 0.1 残差可以恢复退出资格，但不新增开仓、不修改原库存和收益。
2. SAGA 严格一致继续走现有数量风险恢复流程。
3. 负差额、超限、NaN/Infinity、无价格/乘数、冻结资产、Gate 多头或缺腿均不得放行。
4. 汇总一致但逐笔账本不一致不能放行；执行结果未知、未解决风险事件不能放行。
5. 当前与前一轮快照不一致、旧快照、锁被占用、双边接口异常或超时不能放行。
6. 标记通过但执行前数量或价格变化时，真实订单接口不得被调用。
7. 多轮轮询、重复验证、进程重启不改变数量或重复确认收益；真实减仓后旧持仓对象不能重复提交。
8. FOK 切片和实际成交后的残余保留精度；发生真实断腿仍然隔离。
9. Gate 或该币种对冲仍活跃时不触发整币尘埃兑换；现有冷却和批量去重回归测试继续通过。

## 发布与回退

先完成代码和自动化，在阿里云只读调用核验器，不主动下单；保存核验结果。部署 main 后由正常对账完成状态变更，已有退出条件决定是否平仓。监控恢复日志、API 异常与残差持仓状态。

关闭残差退出开关即停止新放行，已标记仓位的下单前检查同样受开关控制。回退代码前先重新隔离仍含残差的仓位；任何已经发生的真实成交必须保留，禁止回滚数据库覆盖成交。

## 第二阶段（独立交付）

尘埃暂按零回收结算的收益口径、兑换任务跨重启核销、历史收益修正与事件时间归属单独设计和验证。本次不新建库存账本、不跨持仓合单、不自动清除未知执行风险。完整故障覆盖指已识别分支及不变条件，不代表交易所异常可穷举。

1. 审计既有尘埃任务与真实兑换明细：确认批次、币种、原持仓、实际扣减数量、实收 BNB、手续费、交易所事件时间以及唯一交易编号。不能只凭当前余额变小就判定兑换成功。
2. 复用任务存储实现 `pending -> submitted -> confirmed -> accounted`，超时进入待查询状态，不重新兑换；以交易所唯一编号去重，重启后先查询历史结果。只扩展既有记录缺少的必要字段，不先引入第二套库存系统。
3. 以实际扣减数量按可追溯来源分配回各持仓，累计核销不能超过已确认尘埃。与仍持有的现货、反向策略和用户手动余额隔离；来源不清时停止自动核销并通知。
4. 收益以真实兑换实收、对应历史成本和手续费计算；BNB 的 USDT 估值记录价格及时间，不能冒充交易所直接提供的 USDT 实现收益。缺少成本或价格时显示待核实，不写零值替代。
5. 历史修正先生成只读差异报告和备份，经确认后按交易所事件时间幂等回填。检查持仓、资金累计、每日收益之间的勾稽关系，避免重复计入或归属到修复当天。
6. 自动化覆盖兑换成功但响应丢失、落库失败、重复回调、限频冷却、部分兑换、重启续跑、跨日归属和历史重复回填；先只读比对，再逐步启用核销。
