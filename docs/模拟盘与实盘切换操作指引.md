# 模拟盘与实盘切换操作指引

## 当前架构概览

```
┌─────────────────┐     HTTP POST      ┌──────────────────────┐
│ TradingExecutor │ ──────────────────► │ executor_service.py  │
│ ClosingExecutor │   /api/execute      │ (VirtualExecutor)    │
└────────┬────────┘                     └──────────────────────┘
         │                                      ▲
         │ config.yaml                          │
         │ trade.executor.url ─────────────────►│
         │ = http://localhost:8081
         │
    ┌────▼────┐
    │ 本地 DB │  mi_trade_order / mi_trade_position
    └─────────┘
```

**关键设计**：`TradingExecutor` 和 `ClosingExecutor` 通过 `ExecutorClient` 以 HTTP 方式调用成交引擎，完全不关心底层是虚拟成交还是真实下单。切换只需改 `config.yaml` 中的 URL 指向。

---

## 阶段一：接入模拟盘（Testnet）

### 目标
验证真实下单 → 成交 → 回报的全链路是否通畅。

### 1.1 申请 Testnet API Key

| 交易所 | Testnet 地址 | 说明 |
|--------|-------------|------|
| Binance Spot | https://testnet.binance.vision | 注册后自动分配测试余额 |
| Gate Futures | https://fx-api-testnet.gateio.ws | 需单独申请合约 Testnet |

> **注意**：Gate 的合约 Testnet 可用标的有限（通常只有 BTC_USDT、ETH_USDT 等主流标的），模拟盘阶段建议先用这些主流标的验证。

### 1.2 编写 RealExecutor 服务

创建 `src/api/real_executor_service.py`，要求：

1. **暴露与 VirtualExecutor 完全相同的接口**：
   - `POST /api/execute` — 接收 order_group + orderbook_row，返回 `{success, message, spot_order, future_order}`
   - `POST /api/reload` — 重新加载配置
   - `GET /api/health` — 健康检查

2. **内部实现替换为真实下单**：
   ```
   收到 execute 请求
     → 解析 order_group 中的 exchange_params
     → 向 Binance 发送现货市价单
     → 向 Gate 发送期货市价单
     → 等待成交回报（轮询或 WebSocket）
     → 组装返回结果（exec_price, exec_qty, exec_amount）
   ```

3. **返回格式必须一致**（ExecutorClient 期望的格式）：
   ```json
   {
     "success": true,
     "message": "成交成功",
     "spot_order": {
       "exec_price": 67230.50,
       "exec_qty": 0.00148,
       "exec_amount": 99.50,
       "coverage_ratio": 0.12
     },
     "future_order": {
       "exec_price": 67250.00,
       "exec_qty": 0.00148,
       "exec_amount": 99.53,
       "coverage_ratio": 0.08
     }
   }
   ```

### 1.3 配置文件新增 Testnet 区块

在 `config.yaml` 中新增：

```yaml
# 交易所 API 配置
exchange:
  # 环境: testnet / mainnet
  env: testnet

  binance:
    testnet:
      base_url: https://testnet.binance.vision
      api_key: "YOUR_TESTNET_API_KEY"
      api_secret: "YOUR_TESTNET_API_SECRET"
    mainnet:
      base_url: https://api.binance.com
      api_key: "YOUR_MAINNET_API_KEY"
      api_secret: "YOUR_MAINNET_API_SECRET"

  gate:
    testnet:
      base_url: https://fx-api-testnet.gateio.ws
      api_key: "YOUR_TESTNET_API_KEY"
      api_secret: "YOUR_TESTNET_API_SECRET"
    mainnet:
      base_url: https://api.gateio.ws
      api_key: "YOUR_MAINNET_API_KEY"
      api_secret: "YOUR_MAINNET_API_SECRET"
```

### 1.4 切换执行器指向

```yaml
trade:
  executor:
    url: http://localhost:8082    # 指向 RealExecutor（Testnet）
```

### 1.5 启动与验证

```bash
# 1. 启动 RealExecutor 服务（Testnet 模式）
cd src && python -m uvicorn api.real_executor_service:app --port 8082

# 2. 健康检查
curl http://localhost:8082/api/health

# 3. 启动主服务（orderbook_server），它会通过 ExecutorClient 调用 8082
cd src && python -m uvicorn api.orderbook_server:app --port 8080
```

### 1.6 验证清单

| 验证项 | 预期结果 | 通过标准 |
|--------|----------|----------|
| 健康检查 | 返回 `{"status": "ok", "engine": "real_testnet"}` | HTTP 200 |
| 现货下单 | Binance Testnet 接受订单并返回 orderId | 非空 orderId |
| 期货下单 | Gate Testnet 接受订单并返回 id | 非空 order id |
| 成交回报 | exec_price/exec_qty 非零 | 数值合理 |
| 全链路延迟 | 从发送请求到返回结果 | < 2000ms |
| 订单记录 | mi_trade_order 表中 channel = 'Real_Testnet' | 记录完整 |
| 持仓创建 | mi_trade_position 表新增 holding 记录 | 字段正确 |
| 平仓测试 | 手动触发或等待条件满足后成功平仓 | status → closed |

## 阶段二：接入实盘（Mainnet）

### 前提条件

- [ ] 模拟盘已稳定运行 ≥ 3 天，无异常
- [ ] 下单/成交/回报链路延迟稳定
- [ ] 平仓逻辑（止盈/止损/强平）均已验证通过
- [ ] 风控机制已确认生效

### 2.1 配置切换（唯一的代码改动）

```yaml
exchange:
  env: mainnet    # testnet → mainnet

trade:
  executor:
    url: http://localhost:8082    # 不变，RealExecutor 根据 env 读取对应配置
```

### 2.2 策略参数调整

```yaml
trade:
  open:
    amount_usdt: 50              # 从测试值改为灰度值（先跑极小金额）
  
capital:
  binance_initial: <实际入金>    # 改为真实初始余额
  gate_initial: <实际入金>
```

### 2.3 订单渠道标识

`_save_orders` 中的 `channel` 字段需要区分环境：

```python
# 当前写死为 'Mock'，切实盘后应动态读取：
order['channel'] = config.get('exchange.env', 'Mock')  
# 值为: Mock / testnet / mainnet
```

### 2.4 灰度上线步骤

```
Step 1: 入金极小额度（如 Binance 200 USDT + Gate 200 USDT）
Step 2: 限制 max_contracts=2，只监控 BTC + ETH
Step 3: 设置 amount_usdt=50，单笔极小
Step 4: 运行 24 小时，观察：
         - 订单是否正常成交
         - 持仓记录是否正确
         - 盈亏计算是否与交易所一致
Step 5: 确认无误后，逐步放大：
         - 增加标的数量
         - 提高单笔金额
         - 增加入金规模
```

## 阶段三：数据源渐进替换（实盘稳定后）

实盘运行稳定后，可逐步将"本地虚拟计算"替换为"交易所真实数据"：

### 3.1 替换优先级

| 优先级 | 模块 | 当前实现 | 替换为 | 复杂度 |
|--------|------|----------|--------|--------|
| P1 | 资金余额 | `capital_tracker.py` 虚拟计算 | 拉 Binance/Gate 账户余额 API | 低 |
| P2 | 资金费结算 | `position_tracker.update_funding_pnl()` 模拟 | 拉 Gate 资金费历史 API | 低 |
| P3 | 期货未实现盈亏 | `position_pnl_calculator` 本地算 | 拉 Gate 持仓 API 的 unrealised_pnl | 低 |
| P4 | 对账机制 | 无 | 新增定时任务对比本地 vs 交易所 | 中 |

### 3.2 不可替换的部分（始终需要本地维护）

- **套利对关联**：哪笔现货对应哪笔期货，交易所不知道
- **跨所总盈亏聚合**：现货盈亏 + 期货盈亏 + 资金费 - 手续费
- **策略逻辑**：开仓信号、峰值回落、止盈判断等
- **历史记录**：订单表、信号表、资金费明细表

### 3.3 对账机制设计

```
每 5 分钟执行一次：
  1. 拉取 Binance 现货余额中所有非 USDT 资产
  2. 拉取 Gate 期货所有持仓
  3. 与本地 mi_trade_position (status='holding') 比对
  4. 不一致时：
     - 本地有但交易所无 → 告警（可能漏平仓）
     - 交易所有但本地无 → 告警（可能漏记录）
     - 数量不一致 → 告警（可能部分成交未处理）
```

## 风控加固清单

切实盘前必须确认以下风控机制已就绪：

### 必备项

- [ ] **单笔金额上限**：`amount_usdt` 不超过总资金的 X%
- [ ] **日亏损熔断**：当日累计亏损超阈值时自动停止开仓
- [ ] **异常停机**：连续 N 次下单失败时暂停服务并告警
- [ ] **余额检查**：下单前检查可用余额是否足够
- [ ] **部分成交处理**：市价单可能部分成交，需正确处理剩余数量
- [ ] **网络超时兜底**：下单后未收到回报时的查询补偿机制

### 建议项

- [ ] **微信/钉钉告警**：关键事件实时通知（开仓、平仓、异常）
- [ ] **每日对账报告**：自动生成本地 vs 交易所的对账结果
- [ ] **手动熔断开关**：前端一键停止所有交易的紧急按钮
- [ ] **API 调用频率监控**：避免触发交易所限流
