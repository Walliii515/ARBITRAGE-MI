# Gate 全仓保证金规则

正向策略固定使用 Gate 全仓模式。现货腿在 Binance，Gate 永续空头腿共享账户保证金，不存在正向逐仓配置、逐币追保或单仓保证金比例。

## 核心口径

系统使用 Gate 账户级风险指标：

```
账户 MMR = Gate accounts 接口 cross_mmr * 100
可用率 = Gate 可用资金 / Gate 账户权益 * 100
```

本地的“账户权益 / 维持保证金合计”只用于一致性审计，不覆盖 Gate 官方 `cross_mmr`。

同时读取各合约的强平价，并计算当前价格到最近强平价的距离。资金监控展示 Gate 账户 `cross_initial_margin`，持仓监控展示并按本地持仓份额分摊 Gate 合约 `initial_margin`；这两个字段只表示交易所初始保证金占用，不代表币种独占抵押物，也不用于推导合约或单仓 MMR。单个合约返回的 `position.margin` 不参与正向策略。

## 开仓风控

- Gate 全仓风险状态为 `warning`、`danger` 或 `unknown` 时，禁止所有正向新开仓。
- 账户 MMR `<=500%` 进入 `warning`：停止新的正向开仓并写入铃铛。左侧正向开仓开关开启时，系统同时创建账户级 Binance → Gate 自动划转任务，目标 MMR 为 `700%`；关闭开关只停止创建新任务，已创建的任务继续执行到完成或异常。
- 账户或持仓接口异常、风险字段缺失、实时快照超过 `5s` 均进入 `unknown`；未知状态本身不触发平仓。
- 风险采集每秒刷新，资金监控每 `2s` 读取实时快照；分钟资金快照继续落库用于 MMR、可用率、占用率和强平距离的历史分析。
- 资金监控同时展示账户/持仓数据年龄、采集耗时、来源和错误。`warning`、`danger`、`unknown` 会由实时采集链路写入左上角铃铛，不等待分钟资金快照。
- Gate 下单后的可用资金不得低于账户总资金的 `15%`。
- Binance 下单后的可用资金不得低于账户总资金的 `15%`。
- 单币集中度由等额 Binance 现货腿控制，普通上限为 Binance 总资金的 `15%`；符合优质加仓条件时最高为 `25%`。
- Gate 不再按币种计算保证金集中度。

## 持仓与平仓风控

- 只有账户/持仓风险快照在 `5s` 新鲜度内才允许风险平仓；`danger` 可启动 MMR 恢复事件或对应合约强平距离退出，已启动的 MMR 恢复事件可在 `warning` 区间继续到 `500%`。`unknown`、`idle` 和陈旧快照不会触发平仓。
- 账户 MMR 在 `(300%, 350%]` 时，只有最近一次自动划转评估明确为“可划资金不足”，才生成一张一次性盈利释放许可；系统找到净收益为正的候选并取得币种级执行权后才领取。领取期间人工/自动划转任务都不能创建；拒单或异常会释放预约但不立即重算，真实卖出 Binance 现货后才立即唤醒划转重算。重算再次确认不足前不释放下一笔。活动划转、自动失败锁、陈旧资金摘要、异常或非有限经济数据、无法取得实时经济口径或没有盈利候选时均不触发该阶段。
- 账户 MMR `<=300%` 进入分步恢复模式，每份新鲜风险快照最多成功平一笔；MMR 恢复到 `500%` 后立即停止。系统先筛选能有效释放维持保证金的候选，再优先预计损失较小的完整套利仓位。真实卖出 Binance 现货后立即唤醒自动划转重算；已有划转任务时只继续该任务，不重复创建。
- 账户 MMR `<=200%` 进入最高级安全路径，不再按盈亏排序：先处理强平距离 `<=300bps` 的合约，再按维持保证金释放能力排序。该路径仍一次只退出一个本地完整套利仓位，不提交跨持仓聚合全平；释放 Binance 资金后同样立即重算自动划转。
- 强平距离 `<=300bps` 是独立危险条件，只平对应 Gate 合约关联的本地持仓，不等待账户 MMR 降到任何阈值。每笔先以 Gate `reduce-only` 市价买回期货空头，再卖出 Binance 现货腿；成功后必须等待更新的 Gate 账户快照再决定是否继续，任一腿失败立即停止本轮。
- 危险平仓独立于盘口、WS、交易连通性熔断和普通平仓失败冷却，使用 Gate `reduce-only` 市价语义全量买回。
- Gate 期货腿成交后立即处理 Binance 现货腿；Binance 价格区间拒单只对剩余现货执行有界重试，未知订单状态先查单且不盲目重发。断腿由即时对账和自动兜底继续处置，所有路径只减仓、不补开缺失腿。
- `100%` 是 Gate 交易所强平的基准线，最终仍以交易所返回的强平价和实际风控结果为准；系统目标是在到达该线前完成主动处置。
- 全仓模式不执行逐币追加保证金。自动补资是账户级 Binance → Gate 资金迁移，不计算单币或单仓 MMR，也不向某个 Gate 仓位单独加保证金。

## 自动划转金额

仅使用健康的新鲜 Gate 官方风险快照和不超过 `120s` 的 Binance 资金摘要。Gate MMR、账户权益、维持保证金、Binance 总资产、Binance Forward 可用余额和交易所最低划转额必须为有限数值；其中维持保证金与 Binance 总资产必须大于 `0`，可用余额和最低划转额不得为负数。任一条件不满足时，不创建任务、不触发 `350%` 盈利释放并写入铃铛：

```
所需额 = max(0, Gate维持保证金 * 7 - Gate账户权益) * 1.15
Binance保留额 = max(Binance总资产 * 2%, 50 USDT)
单次上限 = min(Binance Forward可用资金 * 70%, Binance Forward可用资金 - Binance保留额)
最低有效额 = max(100 USDT, Gate维持保证金 * 50%, 交易所最低额)
实际划转额 = min(max(所需额, 最低有效额), 单次上限)
```

实际划转额不足最低有效额时不提现，并写入铃铛通知人工处理。系统一次只允许一个资金划转任务；任务创建的网络预检、已落库任务和 `350%` 盈利释放共享同一互斥通道。自动任务异常后不重复提现，直到 Gate MMR 恢复到 `700%` 后才开始新的自动补资事件。

## 当前主要配置

```yaml
trade:
  open:
    min_binance_available_ratio: 0.15
    min_gate_available_ratio: 0.15
    max_asset_exposure_ratio: 0.15
    quality_scale_in:
      enhanced_ratio: 0.25

account_capital:
  gate_cross_risk:
    poll_interval_sec: 1
    max_age_sec: 5
    warning_mmr_pct: 500
    profit_release_mmr_pct: 350
    danger_mmr_pct: 300
    critical_mmr_pct: 200
    warning_liq_distance_bps: 600
    danger_liq_distance_bps: 300
    min_available_pct: 15
    notification_enabled: true
    warning_notification_cooldown_sec: 3600
    danger_notification_cooldown_sec: 300
    unknown_notification_cooldown_sec: 300
    auto_fund_transfer:
      enabled: true
      trigger_mmr_pct: 500
      target_mmr_pct: 700
      target_buffer_ratio: 0.15
      max_binance_free_ratio: 0.70
      binance_equity_reserve_ratio: 0.02
      binance_absolute_reserve_usdt: 50
      minimum_amount_usdt: 100
      minimum_mmr_uplift_pct: 50
      attempt_cooldown_sec: 10
```

反向策略如需配置 Gate future 杠杆，使用独立的 `reverse_arbitrage.execution.gate_leverage`。
