# 保证金规则

本文档记录当前实盘使用的 Gate 逐仓保证金风控规则。系统的现货腿在 Binance，合约腿在 Gate；保证金风险主要来自 Gate future 空头腿。

## 核心口径

系统不再使用“距爆仓百分比”作为主要追保和平仓依据，而是使用 Gate 页面同口径的：

```
保证金/维持保证金 = (逐仓保证金 + 未实现盈亏) / 维持保证金 * 100
```

这个指标越高越安全。浮亏时，未实现盈亏会降低仓位权益，因此必须计入分子；只看逐仓保证金会高估安全垫。

## 当前配置

```yaml
margin:
  leverage: 5
  warning_pct: 250
  topup_pct: 250
  close_threshold_pct: 150
  topup:
    enabled: true
    target_maintenance_margin_rate_pct: 350
    max_topup_open_notional_multiplier: 2
    min_gate_available: 50
    cooldown_sec: 60
    min_amount_usdt: 0.1
trade:
  position:
    gate_risk_cache_sec: 10
```

## 风控层级

1. `保证金/维持保证金 >= 250%`
   - 正常状态，不追保。

2. `保证金/维持保证金 < 250%`
   - 进入自动追保流程。
   - 如果可追保，系统向 Gate 该合约逐仓仓位追加保证金。
   - 目标是把该合约仓位补到 `350%`。

3. `保证金/维持保证金 < 150%`
   - 进入紧急区。
   - 系统仍会先尝试追保。
   - 只有追保失败、不可追保、余额不足、超过金额上限等情况下，才触发两端同时平仓。

## 自动追保规则

追保以 Gate 合约为单位聚合处理，而不是按本地每条持仓孤立处理。同一个合约如果有多笔本地持仓，系统会先把它们聚合成一个 Gate 合约仓位口径，再决定是否追保。

触发条件：

- `margin.topup.enabled = true`
- Gate 该合约 `保证金/维持保证金 < topup_pct`
- 该合约不在追保冷却期
- Gate 可用余额追保后仍满足 `min_gate_available`
- 本次追保金额不低于 `min_amount_usdt`
- 累计追保金额没有超过金额上限

冷却规则：

```
同一 Gate 合约两次追保至少间隔 60 秒
```

这个冷却是合约级别的，避免同一个 Gate 聚合仓位在短时间内被多条本地持仓重复触发追保。

风险快照规则：

```
Gate 实仓风险快照缓存 10 秒
```

系统用 Gate 实仓的 `margin / unrealised_pnl / maintenance_margin` 计算保证金/维持保证金。缓存时间越短，越能提前追保，但 Gate 持仓 API 请求会更频繁。

## 追保金额上限

`max_topup_per_position` 次数上限已经废弃。当前不再按追保次数限制，而是按累计追保金额限制。

当前规则：

```
同一 Gate 合约累计追保金额 <= 该合约本地持仓开仓名义金额合计 * 2
```

其中：

- 本地持仓开仓名义金额优先取 `spot_open_amount`
- 如果没有 `spot_open_amount`，则回退为 `abs(future_open_qty) * future_open_price`
- 同一 Gate 合约下有多笔本地持仓时，先求和后再乘以 `2`
- 已追保金额按该合约下本地持仓的 `margin_topup_total` 聚合统计

示例：

```
HMSTR 有 5 笔本地持仓，每笔开仓名义金额约 10 USDT
合约聚合开仓名义金额 = 50 USDT
累计追保上限 = 50 * 2 = 100 USDT
```

如果一次追保计算出的需求金额超过剩余额度，系统会把本次追保金额压到剩余额度内；如果剩余额度低于 `min_amount_usdt`，本轮不再追保。

## 与平仓的关系

追保优先级高于保证金紧急平仓：

1. 先判断是否需要追保。
2. 能追保则追保，并跳过本轮保证金紧急平仓。
3. 如果已经低于 `150%`，但追保失败或不可追保，才触发两端同时平仓。

也就是说，`close_threshold_pct = 150` 是兜底线，不是看到低于 150% 就无条件立刻平仓。

## 前端展示口径

持仓监控中的 Gate 保证金相关字段按以下口径展示：

- `保证金/维持保证金`：Gate 合约聚合口径，和 Gate 页面 MMR 对齐
- `当前保证金`：Gate 合约保证金按本地持仓权重分摊后的行级展示
- `追加金额`：本地该条持仓已记录的累计追保金额
- 汇总行：对金额字段求和，对比例字段按其定义展示或聚合

由于 Gate 页面按合约聚合展示，而系统本地可能把同一个合约拆成多笔持仓，所以单行展示值可能是分摊值；判断是否追保时使用合约聚合值。
