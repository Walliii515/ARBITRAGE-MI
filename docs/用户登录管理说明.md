### 2. 初始化数据库表

执行 SQL 脚本创建用户表:

```bash
mysql -u root -p crypto_arbitrage < src/sql/init_users.sql
```

或手动执行 SQL:

```sql
CREATE TABLE IF NOT EXISTS mi_users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    password VARCHAR(100) NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

INSERT INTO mi_users (username, password) VALUES ('admin', 'admin123');
```

**默认账号**:
- 用户名: `admin`
- 密码: `admin123`

---

### 3. 配置认证参数 (可选)

编辑 `src/config/config.yaml`:

```yaml
auth:
  # Token 签名密钥 (生产环境务必修改为强随机字符串)
  secret_key: 'arbitrage-mi-secret-key-2026'
  # Token 有效期 (秒)，默认 1 小时
  token_expire_seconds: 3600
```

**安全建议**:
- 生产环境务必修改 `secret_key` 为强随机字符串
- 可使用以下命令生成随机密钥:
  ```python
  import secrets
  print(secrets.token_urlsafe(32))
  ```

## 使用说明

### 登录
1. 访问系统首页 (http://localhost:5173)
2. 如果未登录,会自动跳转到登录页面
3. 输入用户名和密码,点击"登录"
4. 登录成功后跳转到订单簿监控页面

### 登出
1. 在左侧菜单栏底部点击"退出登录"按钮
2. 系统会清除登录状态并跳转回登录页面

### 自动登出
- 如果用户 **1小时** 内没有任何操作 (点击、键盘、鼠标移动、滚动)
- 下次操作时会自动登出并跳转到登录页面
- 持续操作不会触发自动登出

## 技术实现

### 认证流程
```
用户登录 → 验证用户名密码 → 生成签名 token → 前端存储 token
                                           ↓
每次请求 → 携带 token → 后端验证签名和过期 → 允许/拒绝访问
                                           ↓
1小时无操作 → 前端清除 token → 跳转登录页
```

### Token 方案
- 使用 `itsdangerous.URLSafeTimedSerializer` 生成签名 token
- 服务端无状态,无需额外存储 session
- Token 包含用户信息 (username, user_id)
- Token 带时间戳,自动过期

### 架构合规性
严格遵守系统分层架构规范:
- 认证逻辑在 `api/` 层 (API 服务层)
- 数据库操作使用 `db_manager.get_cursor()`
- 配置从 `config.yaml` 读取
- 使用 `get_logger(__name__)` 记录日志

## 常见问题

### Q: 忘记密码怎么办?
A: 直接修改数据库中的密码:
```sql
UPDATE mi_users SET password = '新密码' WHERE username = 'admin';
```

### Q: 如何添加新用户?
A: 直接在数据库中插入:
```sql
INSERT INTO mi_users (username, password) VALUES ('newuser', 'password123');
```

### Q: Token 过期时间如何调整?
A: 修改 `src/config/config.yaml` 中的 `auth.token_expire_seconds`

### Q: 生产环境需要注意什么?
A: 
1. 务必修改 `auth.secret_key` 为强随机字符串
2. 建议使用 HTTPS 传输
3. 建议使用 bcrypt/argon2 对密码进行哈希存储
4. 添加登录失败次数限制,防止暴力破解
