# 开仓风控规则文档

> 本文档描述了当前前端实现的3个开仓风控过滤逻辑，用于后续后端风控模块的开发参考。

---

## 概述

系统通过3个维度的风控过滤来评估套利机会的可行性：

1. **资金费率过滤** - 评估资金费率收益是否达标
2. **开仓盘口阈值过滤** - 评估盘口流动性是否充足
3. **开仓边际基差过滤** - 评估开仓利润空间是否足够

所有过滤条件默认开启，采用 **AND 逻辑**（同时满足才会显示）。

---

## 1. 资金费率过滤

### 过滤条件
```
24h资金费率 >= 费率阈值
```

### 字段说明
- **24h资金费率** (`funding_rate_24h`): 当前合约的24小时资金费率
- **费率阈值** (`funding_threshold_percentile`): 从配置指定的百分位字段读取

### 配置项
```yaml
trade:
  funding_rate_threshold_percentile: percentile_30  # 可选: percentile_20, percentile_30, percentile_40
```

### 数据来源
- 表: `mi_gate_future_funding_rate_threshold`
- 字段: 根据配置动态读取（如 `percentile_30`）
- 关联: 通过 `contract = base_asset + "_USDT"` 关联

### 计算逻辑
```python
# 从数据库读取阈值
threshold = threshold_meta.get(contract_name)  # 例如: 0.0003 (0.03%)

# 过滤判断
if funding_rate_24h >= threshold:
    通过过滤
```

### 边界处理
- 如果 `funding_rate_24h` 或 `threshold` 为空，则通过过滤（不排除）

---

## 2. 开仓盘口阈值过滤

### 过滤条件
```
开仓盘口覆盖 <= 盘口覆盖阈值
```

### 字段说明
- **开仓盘口覆盖** (`open_coverage`): 衡量盘口流动性是否充足
  - 计算公式: `max(现货开仓盘口覆盖, 合约开仓盘口覆盖)`
  - 值越小表示流动性越充足
  - 值 > 1 表示盘口不足，无法完全覆盖
- **盘口覆盖阈值** (`orderbook_coverage_threshold`): 最大可接受的覆盖率

### 配置项
```yaml
trade:
  orderbook_coverage_threshold: 0.8  # 80%的盘口覆盖要求
```

### 计算逻辑
```python
# 各侧独立覆盖率
spot_open_coverage = trade_value / spot_ask_total
future_open_coverage = trade_value / future_bid_total

# 开仓盘口覆盖：取最大值（反映最差覆盖情况）
open_coverage = max(spot_open_coverage, future_open_coverage)

# 过滤判断
if open_coverage <= 0.8:
    通过过滤
```

### 边界处理
- 如果 `open_coverage` 为空，则通过过滤（不排除）

### 盘口覆盖计算详情

#### 现货开仓盘口覆盖
```python
spot_ask_total = sum(spot_price_ask_i * spot_volume_ask_i for i in 1..5)
spot_open_coverage = (hedged_qty * current_price) / spot_ask_total
```

#### 合约开仓盘口覆盖
```python
future_bid_total = sum(future_price_bid_i * future_volume_bid_i * quanto_multiplier for i in 1..5)
future_open_coverage = (hedged_qty * current_price) / future_bid_total
```

## 3. 开仓边际基差过滤

### 过滤条件
```
开仓边际基差 >= 开仓边际基差阈值
```

### 字段说明
- **开仓边际基差** (`open_marginal_basis_bps`): 扣除所有成本后的净基差收益
- **开仓边际基差阈值** (`open_marginal_basis_threshold_bps`): 最小可接受的边际基差

### 配置项
```yaml
trade:
  risk_relief_bps: 10                    # 风险缓释（bps）
  open_marginal_basis_threshold_bps: -30 # 边际基差阈值（bps）
```

### 计算公式
```
开仓边际基差(bps) = 开仓VWAP基差(bps) + 开仓费率(bps) + 风险缓释(bps)
```

#### 开仓VWAP基差
```
开仓VWAP基差(bps) = (合约开仓VWAP - 现货开仓VWAP) / 现货开WAP * 10000
```

#### 开仓费率
```
开仓费率(bps) = -(现货开仓费率 + 合约开仓费率) * 10000
```

当前实盘开仓和平仓的 Gate future 腿均优先走 maker，策略阈值里的全局 `FUTURE_OPEN_FEE` / `FUTURE_CLOSE_FEE` 仍是保守配置口径；持仓盈亏会按实际执行角色动态计算：future maker 成交用合约表 `maker_fee_rate`，fallback/protective IOC 成交用 `taker_fee_rate`。Binance spot 开/平仍按 taker 费率计。

### 计算逻辑
```python
# 1. 计算开仓VWAP基差
if spot_open_vwap and future_open_vwap:
    open_vwap_basis_bps = (future_open_vwap - spot_open_vwap) / spot_open_vwap * 10000

# 2. 计算开仓费率
open_fee_bps = -(SPOT_OPEN_FEE + FUTURE_OPEN_FEE) * 10000

# 3. 计算开仓边际基差
open_marginal_basis_bps = open_vwap_basis_bps + open_fee_bps + RISK_RELIEF_BPS

# 4. 过滤判断
if open_marginal_basis_bps >= threshold:
    通过过滤
```

### 边界处理
- 如果 `open_marginal_basis_bps` 为空，则通过过滤（不排除）

### 相关列
- `开仓VWAP基差(bps)`: 合约与现货的VWAP差异
- `开仓费率(bps)`: 开仓手续费成本
- `风险缓释(bps)`: 固定值，用于降低开仓门槛

## 组合过滤逻辑

### AND 逻辑
```python
def combined_filter(row):
    return (
        funding_rate_filter(row) and      # 资金费率过滤
        coverage_filter(row) and          # 开仓盘口阈值过滤
        marginal_basis_filter(row)        # 开仓边际基差过滤
    )
```

### 过滤开关
- 每个过滤都有独立的开关控制
- 开关关闭时，该过滤始终返回 `true`（不排除）
- 默认状态：3个过滤全部开启

## 数据依赖

### 数据库表
1. **mi_gate_future_funding_rate_threshold**
   - 字段: `contract`, `percentile_20`, `percentile_30`, `percentile_40`, ...
   - 用途: 资金费率阈值

2. **mi_gate_future_contracts**
   - 字段: `base_asset`, `funding_rate_24h`, `funding_next_apply`, ...
   - 用途: 合约元数据

3. **mi_base_asset**
   - 字段: `base_asset`, `is_valid`
   - 用途: 有效合约列表

### 后端计算模块
- `calculate_hedge_metrics.py`: 计算对冲指标（VWAP、盘口覆盖等）
- `orderbook_server.py`: 整合数据并推送到前端

## 后端风控模块开发建议

### 1. 数据获取
```python
# 获取所有必要数据
def fetch_risk_data():
    return {
        'funding_rate_24h': ...,
        'funding_threshold': ...,
        'open_coverage': ...,
        'open_marginal_basis_bps': ...,
        'config': load_config()
    }
```

### 2. 风控检查函数
```python
def check_open_position_risk(contract_data, config):
    """
    检查是否满足开仓条件
    
    Returns:
        dict: {
            'pass': bool,
            'reasons': list,  # 未通过的原因
            'details': dict   # 各项指标详情
        }
    """
    results = {
        'pass': True,
        'reasons': [],
        'details': {}
    }
    
    # 1. 资金费率检查
    if contract_data['funding_rate_24h'] < contract_data['funding_threshold']:
        results['pass'] = False
        results['reasons'].append('资金费率未达标')
    
    # 2. 盘口覆盖检查
    if contract_data['open_coverage'] > config['orderbook_coverage_threshold']:
        results['pass'] = False
        results['reasons'].append('盘口流动性不足')
    
    # 3. 边际基差检查
    if contract_data['open_marginal_basis_bps'] < config['open_marginal_basis_threshold_bps']:
        results['pass'] = False
        results['reasons'].append('边际基差不足')
    
    return results
```

### 3. 实时监控
```python
def monitor_and_alert():
    """
    实时监控所有合约，触发告警或自动开仓
    """
    while True:
        contracts = fetch_all_contracts()
        config = load_config()
        
        for contract in contracts:
            risk_result = check_open_position_risk(contract, config)
            
            if risk_result['pass']:
                # 满足开仓条件
                send_alert(contract, risk_result)
                # 或自动开仓
                # execute_open_position(contract)
        
        sleep(config['check_interval'])
```

## 注意事项

1. **空值处理**: 所有过滤在数据为空时默认通过，避免误杀
2. **动态配置**: 所有阈值都支持从配置文件动态读取，无需重启
3. **单位统一**: 基差和费率统一使用 bps（基点），1 bps = 0.01%
4. **盘口覆盖**: 取最大值而非最小值，反映最差的流动性情况
5. **风险缓释**: 固定值，用于调整开仓门槛，可根据市场波动调。 整
